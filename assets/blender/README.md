# Blender-authored assets (4B-ASSETS-1)

The first Blender-authored asset iteration for the Ring (the driver's issue-0023:
"the road is covered … the trees are green chunks, not really looking as trees …
real roads have multiple layers, maybe we need to do the same, like actually
putting asphalt on to the roads"). The visual contract is `docs/art-direction.md`
(the canon, verbatim: "large, simple shapes with photographic-looking textures doing
much of the work", "A tree can be mostly cards", "road: repeating 512/1024",
"vegetation: 128-512", "diffuse/albedo texture, subtle normal, very mild roughness
variation", "muted forest / olive greens", "medium cool grey"); the element names are
`docs/design/4b/element-library.md` §1 (road_asphalt_1024) and §6 (V1 / V2 / V4 / V6).

**The scripts under `scripts/` and the exported PNG / .glb files ARE the source of
truth and are committed.** `factory_driver_assets.blend` (312 783 bytes, well under
the 20 MB line at which it would have been gitignored) is a convenience for a human
with Blender open; it is regenerated by `build_all.py`, not edited by hand, and a .blend
is not byte-deterministic (it carries the session's memory layout), so nothing gates on
its bytes.

## Regeneration

Blender **5.2.2 LTS** (`/opt/homebrew/bin/blender`, build 2026-09-15, glTF I/O
v5.2.40), headless, from the repository root:

```
blender -b -P assets/blender/scripts/build_all.py            # everything + the .blend
blender -b -P assets/blender/scripts/asphalt.py              # the road texture set alone
blender -b -P assets/blender/scripts/foliage.py              # the vegetation textures alone
blender -b -P assets/blender/scripts/trees.py                # the three archetypes alone
blender -b -P assets/blender/scripts/build_all.py -- --preview /some/scratch/dir
```

`--preview DIR` writes 2 x 2 tilings and alpha-over-checker composites to DIR for
eyeballing (scratch, never committed). `trees.py` needs the vegetation PNGs on disk
(its materials reference them), so run `foliage.py` first or use `build_all.py`.
The whole build is about 15 s on this machine.

## Determinism (verified 2026-09-26)

Cycles on the CPU, a fixed seed (4711), 16 samples, no denoising, no animated seed;
the textures are EMIT bakes of procedural shader networks onto a unit plane, the
pixels quantised once into 8-bit PNG (Non-Color, so a shader value of x is stored
as x). `build_all.py` run twice in a row: all ten artifacts byte-identical (`cmp`
on tree_spruce.glb, tree_beech.glb, tree_row.glb, the three road PNGs, the four
vegetation PNGs); the three `.glb` through `trees.py` alone identical to the
one-session build's (the image datablock is named the same by either path).
A repair patch is inset in its grid cell, so the tile's border rows are plain
asphalt and the dressing test's seam check (first row against last row, against
neighbouring rows) holds; the bake plane carries a small apron beyond the tile
with periodic UVs so the pixel filter never under-covers a border row.
The glTF JSON is re-serialised by our own packer with sorted keys and no
whitespace, so no field of it depends on dictionary order; the only version-bearing
field is `asset.generator` ("Khronos glTF Blender I/O v5.2.40"), which changes with
the Blender version - a regeneration under another Blender is a new commit, not a
byte-identical one.

Tileability is by construction: every noise / Voronoi is sampled on a 4D torus
(`common.Graph.torus`), so it wraps exactly at the tile's edges; the repair-patch
grid divides the tile; the wheel ruts are a function of u alone.

Every asset has its Godot `.import` beside it, committed: textures VRAM-compressed

scene through Blender and fail headless ("Blender path is invalid or not set").

### The asphalt set (`asphalt.py`) - authored only; the wiring is a later stage

GREYSCALE-NEUTRAL (R = G = B everywhere): the game multiplies its region tint
(`RoadBuilder.ASPHALT_TINT`, the canon's "medium cool grey"); the mean is authored
at 0.78 because the procedural texture it will replace (`scripts/asphalt_texture.gd`,
BASE_BRIGHTNESS 0.78) had that mean, so the tinted road keeps its value.
The layered-road look, coarse to fine: the aged lighter body with exposed aggregate;
two polished wheel ruts per lane, darker and (in the roughness map) smoother, with a
shallow dip in the height the normal map is derived from; the lighter centre between
the lanes and at each lane's centre; shoulder grime darkening toward u 0 and u 1 into
the gravel; an occasional repair patch, a rectangle of the tile's own 4 x 3 grid,
darker with a visible seam line; fine aggregate grain; sparse pale stones and dark pits.

**THE UV CONTRACT** (the later `road_builder.gd` wiring maps it; the texture was
authored for exactly this):

> u = (offset - left_paved_edge) / paved_width, so u 0..1 spans the full paved
> cross-section of a strip (shoulder grime at u 0 and 1, wheel ruts symmetric about
> u 0.5); v = chainage_m / TILE_ALONG_M with TILE_ALONG_M = 8.0, so one tile is
> paved_width x 8 m.

The tile is drawn for a two-lane section: lane centres at u 0.25 and 0.75, the two
ruts of each lane a track's width apart (1.6 m of a 6.5 m section, ±0.12 in u), so
the four ruts stand at u 0.13 / 0.37 / 0.63 / 0.87. On a section wider or narrower
than 6.5 m the ruts scale with it (u is normalised), which is the accepted cost of a
single tile: the pit lane and a village street share it. The direction of v does not
matter (nothing in the tile is oriented along the road). The normal map is Godot's
convention (+Y up, OpenGL); wire it with `normal_scale` well under 1 for the canon's
"subtle normal".

### The vegetation textures (`foliage.py`)

Greyscale-neutral too - the region's tint table (`data/regions/eifel_ring/
dressing.json`, V4_front / V4_middle / V4_back / V2 / V1 / trunk) colours them as
the vertex colour, so "spruce blue-green over beech" and the luminance cap stay the
table's business. Godot reads v downwards: a card's top is v 0 there and v 1 in
Blender; the glTF exporter flips v for the meshes, and `forest_walls.gd` maps the
wall card's top to v 0 by hand.

* `foliage_wall_512.png` - the V4 forest-wall card: an opaque canopy body with tree
  columns and three waved canopy tiers (darker undersides), the spruce tops a jagged
  alpha skyline in the upper third, holes of sky just under it. A card offsets u by
  its hash and mirrors by another, so neighbours show different skylines.
* `foliage_spruce_512.png` - LEFT HALF (u 0..0.5, the full height) the spruce side
  card: a tapering silhouette of ten drooping tiers with ragged tips, gaps above the
  fringes here and there, the trunk dark up the middle; RIGHT-TOP quadrant the
  branch whorl seen from above (a nine-pointed star of alpha) for the tier cones;
  RIGHT-BOTTOM quadrant a sparser six-pointed whorl for the top two tiers.
* `foliage_beech_512.png` - LEFT HALF the beech crown card, an irregular chunky
  crown of lumped clusters with holes of sky; RIGHT HALF a leaf-cluster fill,
  tileable within the half, that the crown lobes wear.
* `bark_256.png` - vertical ridges and dark fissures; wraps once around a trunk and
  every 2 m up it.

### The tree archetypes (`trees.py`)

Each is one mesh with two material slots, `bark` (bark_256.png, opaque) and
`foliage` (the atlas, alpha MASK at 0.5, double-sided), one glTF primitive each, so
Godot reads two named surfaces. The origin is the foot of the trunk, +Y up. Foliage
normals are authored: a vertex's direction from the trunk axis blended with up, so
crossed cards and whorls light like one rounded mass whichever way they face.

* **tree_spruce** (V2, the Eifel default), 20 m: tapered 8-sided trunk (16 tris), three
  crossed side cards (6), seven whorl cones of 12 segments stacked up the trunk and
  shrinking (84). 106 triangles.
* **tree_beech** (V1), 14 m: the trunk (16), three chunky low-poly lobes (6 x 3 UV
  spheres, 36 each), three crossed crown cards (6). 130 triangles.
* **tree_row** (a V1 standing in a V6 tree row), 10 m: the trunk (16), three smaller
  lobes (108), two crossed cards (4). 128 triangles.

Export: `GLTF_SEPARATE` with `export_keep_originals` (the image URIs point at the
committed PNGs, `../textures/vegetation/…`), then `pack_glb()` folds the .gltf and
.bin into one .glb keeping those URIs - Blender's own GLB path embeds the images and,
with keep_originals, also writes the URI beside the embedded copy, which is not valid
glTF. Blender 5 has no material blend mode any more, so the exporter writes alphaMode
BLEND for a linked alpha; the packer sets MASK / cutoff 0.5. Godot resolves the
relative URIs to `res://assets/textures/vegetation/…` and shares the textures.

## How the game uses them (this stage)

`scripts/forest_walls.gd` reads each archetype's two surfaces once from the imported
scene and bakes a transformed copy per tree (hashed yaw, uniform scale to the tree's
height over the archetype's, its point) into the same per-kilometre chunk
ArrayMeshes as before, with the archetype's UVs and the tint as the vertex colour;
V4 cards are the same quads UV-mapped into the wall texture; four
StandardMaterial3Ds replace the one flat material. Placement is untouched. The
asphalt set is NOT wired yet: `road_builder.gd` belongs to another job; the UV
contract above is what it will map.

## Known limits, honestly

* The textures are procedural shader networks baked in Blender, not photographs:
  "photographic-looking" is approached by layered noise, grain, stones, seams and
  silhouettes. A later pass may replace a tile with a licensed photo scan authored
  to the same UV contract and names.
* The tree archetypes are 106-130 triangles, over V1's "≤ 120" for the beech by 10
  (the third lobe); the canon's 2000 look is carried by the cards and the alpha,
  not the polygon count.
* No V3 billboard yet: every tree is its near archetype at every distance
  (deferred since 4B-7).
